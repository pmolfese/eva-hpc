## Concrete algorithm issues and limitations

1. Rust `aas_donors` averages accepted consecutive epochs in a section without
   separating acquisition groups. Slice-position-specific waveforms can therefore
   be mixed. FASTR/FARM/Moosmann donor selection does require matching group indices.
   This is a plausible mechanism for the observed AAS slice-mode failure, independent
   of acquisition gaps. A group-specific AAS change needs regression and parity work.
2. Count-based scheduling assumes TR / groups. With TR=2 and 44 slices / MB=2 this
   is 90.909 ms, not the supplied JSON's 90 ms. The final group is placed ~19.09 ms
   later than that JSON specifies. Its last-group-to-next-volume interval is 110 ms.
3. Explicit-offset layout still uses one median epoch length (90 ms here) for every
   group, leaving approximately 19 ms of sample-grid coverage missing near each
   volume boundary (the endpoint itself is inclusive). That region is copied raw.
   Per-group template support and coverage need explicit handling; simply importing
   this JSON is NOT a validated fix and worsened this test.
4. Rounded group starts and alignment can leave additional short uncovered spans
   or overlapping reconstructions. Coverage metrics should distinguish internal
   uncorrected spans from ordinary recording edges.

## Assessment of the release note

Agree: retain elapsed time from epochs.xml, retain event timestamps, never treat
missing samples as measured EEG, split filtering/adaptive state at acquisition
boundaries, exclude gap-overlapping analysis epochs, preserve gaps on export, and
rebuild results made on an incorrect clock. MNE's Raw filter documentation likewise
specifies independent filtering on either side of BAD_ACQ_SKIP annotations:
https://mne.tools/stable/generated/mne.io.Raw.html

Zero placeholders require a mask/annotation honored by every processing stage.
Rust's NaN representation is intentional and must not be replaced blindly.

The macOS guard in GradientViewModel.swift computes support from first TREV minus
one median TR to last TREV plus one TR, clipped to signal bounds. Here that is
[26.808, 437.807) seconds; it cannot intersect the 2.247–2.732 s gap. Refusing a whole
run when a gap intersects support is a conservative policy, not the only valid
algorithm: Rust instead skips invalid windows and restarts ANC on finite segments.
A more precise support test must account for alignment/interpolation/filter context.

The release note's Decision Matrix and PSA claims were not audited in this Rust
investigation; neither their test count nor Swift numerical behavior is established
by the MNE reader comparison. The earlier 465 ms recording in the release note is
not this file, which has a 485 ms gap.

## Reproduction and next steps

`crates/eva-core/examples/check_mri_gap.rs` is a case-specific diagnostic for the
22-group/90 ms comparison, not a new production processing default. Run with input
path and a new output directory; optional final `full` also exercises the shared
whole-recording MRI loader. Raw channel/processed f32le files and diagnostics are
written only to that output directory. Local results are in
`target/gap-investigation/`; `compare_mne.py` and `comparison.json` record the reader
comparison. Synthetic regression confirms that a gap well before support leaves
all four methods' correction within support identical to a finite-prefix control.

Do not roll back clock restoration. Next isolate the exact failing Swift/Rust
settings/backend and confirm the EEG-matched acquisition sidecar, then repair
slice-group donor selection and template coverage with explicit tests. Whole-volume
AAS is the successful comparison condition here; it is not a universal guarantee.
